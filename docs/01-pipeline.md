# 工序与原理

> 本文讲"每一步为什么这么做"。踩坑与判据见 `03-pitfalls.md`；怎么验收见 `04-verification.md`。

## 0. 问题的形状

手里通常只有**一张图**（参考花纹、商品图、实拍照片），而渲染管线要的是**一套可平铺的 PBR 贴图**。这两者之间的差距不是分辨率，而是三件事：

| 差距 | 具体表现 | 本仓库的解法 |
|---|---|---|
| **① 尺度与周期性** | 图是"裁"出来的，拼起来必露缝；也没有"一格多少毫米"的概念 | 量出周期（规则图案）或做无缝化（随机纹理），并标定比例 |
| **② 光照与材质分离** | 照片里烘焙了打光、渐变、阴影；这些不该跟着材质走 | 压平低频光照；色调按参考图**直方图匹配** |
| **③ 通道完备性** | 只有颜色，没有法线/粗糙度/金属度/AO | 从图像的**多尺度分解**推出高度，再派生其余通道；按引擎惯例打包 |

**判断路线**：纹理分两类，处理的数学完全不同 ——

- **规则图案**（编织砖、人字拼、格栅）：核心是**求周期 + 还原块布局**，可以精确重建。
- **随机纹理**（水磨石、斑点石、木纹、水泥）：没有可求的周期，核心是**无缝化**。

## 1. 规则图案：先测量，再重建

### 1.1 量出网格与周期

`scripts/pattern/analyze.py`：统计每列/每行的"亮像素占比"，峰值即**缝的位置**；相邻缝间距即**模数**。

### 1.2 把图案变成"边矩阵"

`scripts/pattern/extract-edges.py`：对每一个格点边界问一句"**这里有没有线**"：

- `V[c][r]`：第 c 条竖边界在第 r 行带内是否画了线
- `H[r][c]`：第 r 条横边界在第 c 列带内是否画了线

于是图案 = 两张 0/1 表。**再对这两张表求最小周期** —— 本例中是 **5×5 个模数**。

### 1.3 合并成块，并核对

`scripts/pattern/reconstruct.py`：把 `V/H` 里"没有线"的相邻格合并成矩形块（**注意跨周期边界的整块**：有的砖会跨过单元接缝，这正是它能无缝平铺的原因）。再把重建结果画成线掩膜与原图比对，得到命中率（本例 95%）。

### 1.4 程序化重建

`scripts/make-texture.mjs` 按周期出图，参数化：缝宽（占模数比例）、倒角、槽底高度、AO 强度、法线强度、色调 LUT。
因为**贴图正好取一个周期**，平铺必然无缝 —— 且可以证明：把任一像素平移一个周期后采样，30 万随机点差异为 0。

## 2. 随机纹理：对折偏移 + 补丁匹配 + 泊松克隆

### 2.1 为什么"对折偏移半张"能行

把图像平移半个宽度（环绕）后：

- **四条外边界天然连续**了 —— 原来的左右边缘被贴到了一起，而它们在原图里本来就是相邻像素；
- **代价**：原来的左右边缘原本"隔着整个画面"，现在跑到**中线**上去对撞，于是中线出现两条缝。

**全局的无缝问题，被浓缩成"补两条细缝"的局部问题。** 这是整条流水线的关键一步。

### 2.2 补缝：SSD 匹配 + 泊松无缝克隆

1. 在**没有缝的区域**里滑窗搜索一条等宽的条带，代价 = **它与缝两侧各 3 列的 SSD**（越小说明接得上）。
2. 把这条带**泊松无缝克隆**进去：解 `∇²f = ∇²patch`，边界取缝外的真值。
   - 用补丁自身的**拉普拉斯**做源 ⇒ 补丁的**纹理细节保留**；
   - 边界取真值 ⇒ **两侧没有任何台阶**；
   - 结果是"细节还在、亮度色差平滑接上"，既没有镜像对称（蝶形）、也没有插值条纹。

### 2.3 缝带宽度：**64px 量级最优**

见 `03-pitfalls.md` **P3**：缝带越窄，失配被压进越短的距离 ⇒ 越"抹平"。实测 16/32/64/128/256px 的"抹平度"指标，**64px 是无可见抹平又改动最小的点**。

### 2.4 压平摄影光照（可选）

`--flatten k`：除以半径 = 图宽/10 的盒式模糊、再乘回全局均值，只压 `k` 比例。
**平扫图不需要**（先量：4×4 块均值波动 ±2% ⇒ 跳过；±10% 以上 ⇒ 压 60%）。

## 3. 从一张底色推出整套 PBR

`scripts/make-material.mjs` 把无缝底色分解成两个尺度（环绕盒式模糊）：

- **细节尺度**（半径 2）：表面微颗粒 / 麻点
- **骨料尺度**（半径 16）：骨料与基体的区域差

然后：

| 通道 | 来源 | 备注 |
|---|---|---|
| **height** | 细节高频（微起伏）+「暗色骨料=略凸」项 | 抛光面整体很平，浮雕要**轻** |
| **normal** | height 的中心差分（环绕） | 强度用物理量 `--bump`（见 P1） |
| **roughness** | 骨料/基体的亮度差加权 | **经验映射**，`--rough-base/--rough-var` 可调 |
| **AO** | 细节高频的**负半部分**（凹处） | 很轻 |
| **metallic** | 恒 0 | 石材/水泥是**电介质**，这是物理正确答案 |

### 打包（三种引擎惯例，一次出齐）

| 文件 | 打包 | 谁用 |
|---|---|---|
| `tile-orm<后缀>.png` | **R=AO ｜ G=Roughness ｜ B=Metallic** | Unreal 直接接；**glTF 2.0 也用同一张**（`occlusionTexture` 读 R、`metallicRoughnessTexture` 读 G/B） |
| `tile-metallicRoughness<后缀>.png` | G=Roughness ｜ B=Metallic | glTF 纯 metallicRoughness 用法 |
| `tile-unity-mask<后缀>.png` | **R=Metallic ｜ G=AO ｜ B=DetailMask ｜ A=Smoothness** | Unity HDRP/Lit 的 Mask Map |

## 4. 预览：自己写一个软件 PBR 渲染器

`scripts/render-material-ball.mjs`：零依赖（自带 PNG 解码）+ **Cook-Torrance GGX** + 三点光 + 环境近似 + ACES 色调映射 + 2×2 超采样，输出：

- **材质球**：球面 UV，但把"极点"旋到 ±X（左右剪影）⇒ 可见面平滑、收敛处藏在轮廓里（否则平铺花纹会在两极汇成"沙滩球"）；
- **实景地面**：透视平面 + 雾化，用来检查"铺开之后有没有接缝、有没有明显重复"。

它同时是**验收工具**：能渲出来，就说明贴图的色彩空间、法线约定、通道打包都是自洽的。
