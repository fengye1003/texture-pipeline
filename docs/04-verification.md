# 验收清单

> 原则：**能用代码测的，不要用眼睛看。**
> 每条都给出**判据 + 复现命令 + 不合格怎么办**。

## 1. 无缝性（最容易被"看着差不多"糊弄过去的一项）

### 1.1 接缝比值（主判据）

**定义**：`左右接缝跳变 ÷ 内部相邻跳变`。

- 分子 = 把左右两列"拼起来"时的平均通道差（也就是平铺后接缝处实际发生的跳变）；
- 分母 = 图像内部相邻列的**平均**跳变（纹理自身的噪声水平）。

**判据**：**< 1.6 视为无缝**（本仓库实测：处理前 2.79~5.18×，处理后 0.78~1.28×）。

`make-seamless.mjs` 会自动打印处理前后的这个比值，并在 **≥ 1.6 时以退出码 1 结束**（便于接 CI）。

### 1.2 补丁区"抹平"检查（只有做过补丁才需要）

**定义**：`缝带中心 16px 的高频能量 ÷ 全图同类条带的中位数`。

**判据**：**≥ 0.85**（1.00 = 完全看不出差别）。低于 0.85 说明补丁区被平滑过度 ⇒ **把缝带调宽**（见 `03-pitfalls.md` P3）。

参考实现：`scripts/figures/compare-band.py`（可直接扫一遍不同缝带宽度，挑最优）。

### 1.3 严格周期检查（规则图案专用）

把像素坐标平移一个周期后重新采样，与原点比较。**判据：最大差异 = 0。**
`make-texture.mjs --verify` 会跑 30 万随机点并打印最大差异。

## 2. 通道打包正确性

`python scripts/verify-maps.py <后缀> [贴图目录]`（默认目录 `out`）逐项断言：

| 断言 | 方法 | 判据 |
|---|---|---|
| 贴图都是正方形 | 读尺寸 | `w == h` |
| `ORM.R == AO`、`ORM.G == Roughness`、`ORM.B == 0` | `ImageChops.difference` 逐通道取极值 | **极值 = (0,0)** |
| `metallicRoughness.G/B` 同上 | 同上 | 极值 = (0,0) |
| `UnityMask` 四通道（含 `A == 255 − Roughness`） | 同上 | 极值 = (0,0) |
| 金属度图全 0（电介质） | 同上 | 极值 = (0,0) |
| **法线是单位长度** | 抽样解码 `n = (2r−1, 2g−1, 2b−1)` 求模 | **\|n\|−1 的最大偏差 < 0.03** |

> 「法线单位长度」这条能一次性抓出"法线强度给错/通道写反/编码错"三类问题，强烈建议保留在 CI 里。

## 3. 视觉终检（渲染，不是看图）

```bash
node scripts/render-material-ball.mjs --suf <后缀> --size 900 --ss 2
```

它同时是**端到端自洽性检查**：能正确渲出来，说明①色彩空间（albedo 必须按 sRGB 解码）②法线约定（OpenGL/DirectX）③通道打包 三者都自洽。

看三件事：

1. **材质球**上有没有异常的接缝、条纹、对称"蝶影"；
2. **实景地面**铺开后有没有可见的重复周期感；
3. 高光形状是否符合材质预期（抛光石材应是紧凑的小高光；哑光应是宽而弱）。

## 4. 交付前最后一遍（机械动作，别省）

1. **哈希比对**：交付目录里的文件与生成器输出**逐文件 sha256 一致**（防搬错版本、防留陈旧文件）。
2. **尺寸与色彩空间**：每张贴图的位数/通道数/色彩空间标注写进规格书。
3. **命名一致**：`tile-<通道><后缀>.png` —— 校验、渲染、出图脚本都靠这个约定互相复用。
4. **授权与来源**：源素材是谁的、能不能对外发布，写清楚（本仓库不含任何第三方素材）。
